# Backend domain modules

QuickBite V1 is a **modular monolith** (`docs/decisions/ADR/0001-modular-monolith.md`).
Each folder below is a NestJS module inside the single backend application — not a microservice.

## Rules

1. A module owns its tables (`docs/database/DATABASE.md` §78). Other modules never query those
   tables directly; they call the owning module's exported service.
2. A module exports only what other modules need (a service facade). Controllers, repositories
   and internal helpers stay private.
3. Cross-module side effects that must survive failures go through the outbox
   (`docs/decisions/ADR/0011-outbox-pattern.md`), not direct calls to external providers.
4. Every protected endpoint follows: Authentication → Identity → Role → Permission →
   Resource Ownership / Tenant → Business Rule → Action (`docs/security/AUTH_AUTHORIZATION.md`).
5. Do not add a module that is not listed here without an approved architecture decision.

`src/infrastructure`: configuration, logging, error envelope, database, Redis, queues, realtime
gateway, health. `idempotency_keys` and `outbox_events` will be implemented there before the
first slice that needs them (`docs/IMPLEMENTATION_PLAN.md` §24).

## Current status

Implemented (Slice 1): `auth`, `users`, `audit`, and the registration part of `customers`.
All other modules are **boundaries only**.
